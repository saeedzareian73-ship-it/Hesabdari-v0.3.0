راهنمای فعال‌سازی فضای ابری و مجوز کاربران
==========================================

پیش‌نیازها
----------
- پوشه برنامه باید روی HTTPS قرار بگیرد (برای نمونه GitHub Pages).
- یک پروژه Firebase به نام و تحت کنترل توسعه‌دهنده بسازید.
- این نسخه برای همگام‌سازی از Firebase Authentication و Cloud Firestore استفاده می‌کند.
- اجرای پشتیبان‌گیری فقط هنگام باز بودن برنامه/ذخیره اطلاعات است؛ نیازی به Cloud Functions یا زمان‌بندی پس‌زمینه ندارد.

۱) ساخت پروژه و ثبت برنامه وب
-----------------------------
۱. وارد https://console.firebase.google.com شوید و پروژه جدید بسازید.
۲. در Project settings > Your apps یک برنامه Web اضافه کنید.
۳. مقادیر apiKey، authDomain، projectId و appId را بردارید.
۴. آن‌ها را در فایل firebase-config.js در پوشه برنامه وارد کنید.
۵. دامنه میزبان برنامه را در Authentication > Settings > Authorized domains اضافه کنید.

۲) فعال کردن روش ورود
---------------------
۱. در Firebase Console به Authentication > Sign-in method بروید.
۲. Google را فعال کنید.
۳. اگر می‌خواهید کاربران با GitHub وارد شوند، GitHub را هم فعال کنید و OAuth App بسازید. آدرس callback که Firebase نمایش می‌دهد باید در تنظیمات OAuth App گیت‌هاب ثبت شود.
۴. کاربران در خود برنامه با ورود OAuth وارد می‌شوند؛ لازم نیست رمز عبور یا Personal Access Token گیت‌هاب را به شما بدهند.

هشدار امنیتی: هرگز GitHub Personal Access Token یا رمز عبور حساب خودتان را به کاربران ندهید. این توکن‌ها مانند رمز عبور هستند و ممکن است دسترسی به مخازن و منابع حساب بدهند. برنامه از ورود OAuth استفاده می‌کند، نه توکن شخصی شما.

۳) ساخت Firestore و قراردادن قوانین
-----------------------------------
۱. در Firebase Console بخش Firestore Database را ایجاد کنید.
۲. در بخش Rules محتوای فایل firebase.rules را قرار دهید و Publish کنید.
۳. در Firestore یک مجموعه به نام access بسازید.
۴. برای هر کاربر مجاز، در مجموعه access یک سند بسازید که Document ID آن دقیقاً UID دریافتی از Firebase Authentication باشد؛ داخل سند فیلد enabled از نوع Boolean و مقدار true قرار دهید. آدرس Gmail به‌جای UID قابل استفاده نیست و سندی با شناسه Gmail در بررسی دسترسی برنامه نقشی ندارد.
۵. ورود با گوگل و مجاز بودن برای همگام‌سازی دو مرحله جدا هستند: ممکن است کاربر با موفقیت وارد حساب شود و UID بگیرد، اما تا زمانی که سند access/{UID} با enabled=true وجود نداشته باشد، فضای ابری برای او فعال نمی‌شود.
۶. برای قطع دسترسی، enabled را به Boolean false تغییر دهید یا سند UID را حذف کنید.

برای پیدا کردن UID، کاربر یک بار از صفحه پشتیبان و خروجی با گوگل یا GitHub وارد می‌شود. UID را می‌توان در Firebase Authentication > Users دید. در صورت مجاز نبودن، برنامه پیام می‌دهد که حساب هنوز توسط مدیر فعال نشده است.

۴) رفتار همگام‌سازی
-------------------
- در شروع برنامه، اگر حساب وارد شده و مجاز باشد، داده ابری و محلی مقایسه می‌شوند.
- اگر ابر داده داشته باشد و دستگاه تازه/خالی باشد، داده ابری دریافت می‌شود.
- اگر ابر خالی باشد، داده همین دستگاه بارگذاری می‌شود.
- اگر هر دو طرف از آخرین همگام‌سازی تغییر کرده باشند، برنامه از کاربر می‌پرسد کدام نسخه نگه داشته شود؛ به‌صورت خودکار داده‌ها را ادغام نمی‌کند تا مانده‌های حسابداری خراب نشوند.
- پس از هر ذخیره، همگام‌سازی با کمی تأخیر انجام می‌شود؛ وقتی برنامه بسته است کاری اجرا نمی‌شود.
- اطلاعات محلی پاک نمی‌شود مگر اینکه خود کاربر فایل پشتیبان بازیابی کند یا داده مرورگر را دستی پاک کند.

۵) هزینه
--------
Firestore در طرح Spark سهمیه رایگان دارد. سهمیه فعلی رایگان شامل ۱ GiB ذخیره‌سازی، ۵۰٬۰۰۰ خواندن سند در روز و ۲۰٬۰۰۰ نوشتن سند در روز است؛ در صورت عبور از سهمیه، عملیات ممکن است محدود شود و برای افزایش سقف باید صورتحساب فعال شود. نسخه فعلی پشتیبان را به‌شکل سندهای عادی Firestore ذخیره می‌کند و از قابلیت Backup/Restore مدیریت‌شده Firestore استفاده نمی‌کند.
